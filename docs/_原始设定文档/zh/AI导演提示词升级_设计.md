# AI 导演提示词升级 — 让事件有后果（MVP 可用）

> 目标：把导演从「只生成一句诡异描述」升级为「选择一个已定义的事件类型 + 配诡异描述」，
> 然后由代码执行该事件的客观后果（掉SAN/瞬移/快进…）。
> 符合架构铁律：**LLM 负责创造（选事件、写描述），代码负责执行（结算后果）。**
> 关联：事件篇_设计.md、核心设定_唯物对抗唯心.md、WorldLore.cs、AIDirector.cs。

---

## 一、为什么要升级

### 现状问题
现在导演只输出 `{"event": "一句描述"}` —— 纯文字，**没有后果**。
玩家很快发现事件只是刷文字、无法应对，于是无视它们。这就是「事件杂乱无章 / 没有意义」的根源。

### 升级方向
导演输出**结构化事件**：从已定义的事件类型里选一个 + 配一句诡异描述。
代码拿到「事件类型」后，执行事件篇里定义好的客观后果。

```
旧：LLM → "一句诡异描述" → 显示在日志（没了）
新：LLM → { 事件类型 + 诡异描述 } → 显示描述 + 代码执行该类型的后果
```

---

## 二、新的导演输出格式

导演输出 JSON：
```json
{
  "type": "事件类型ID",
  "event": "符合该事件的诡异描述文字（1~2句）"
}
```

### MVP 的事件类型ID（与事件篇对应）
| type ID | 对应事件 | 代码要执行的后果（简版，详见事件篇） |
|---|---|---|
| `storm` | 亚空间风暴 | 冲击建筑/机械/电力（MVP 可先只做告警表现） |
| `space_warp` | 空间扭曲 | 随机挑1个NPC，瞬移到随机可站立点，该NPC困惑/恐慌+终止任务 |
| `time_disorder` | 时间失序 | 时钟故障动画 → 游戏时间快进（连消耗一起结算） |
| `causal_reversal` | 因果倒置 | 进入延时状态：建造材料被篡改 + 全屏滤镜；结束后按概率处理期间成品 |
| `whisper_vision` | 低语与幻象 | 低语音效 + 生成可对话幻象（先遣队员/死去NPC） |
| `relic`（探索时） | 不同年代的遗存 | 探索遭遇专用：触发者掉SAN（不由主导演随机触发，归探索逻辑） |

> 注：`relic` 是探索遭遇，由「NPC探索」触发，不在主导演的随机生成池里。
> 主导演随机池 = storm / space_warp / time_disorder / causal_reversal / whisper_vision。

## 三、导演提示词（新版草案）

在原有 Background + WorldLaws 之后，替换 DirectorGuidance / EventThemes 部分：

```
【你的职责：亚空间导演】
你负责在亚空间中制造异常事件，让局势更紧张或更诡异。
事件必须符合设定、压抑诡异、留白（描述"发生了什么"，不解释"为什么"）。
异常度越高，事件应越超出人类理解。

【你只能从以下事件类型中选择一个】（不要自创类型）
· storm（亚空间风暴）：能量异常涌出，冲击营地的设施与机械。
· space_warp（空间扭曲）：空间错乱，有人莫名出现在了别的地方。
· time_disorder（时间失序）：时间感错乱，时间不正常地流逝。
· causal_reversal（因果倒置）：因果被打乱，造物的规则一时变得不可信。
· whisper_vision（低语与幻象）：有人听见低语，或看见已经死去的人。

【当前世界状态（JSON）】
{worldJson}

【输出要求】只输出一个 JSON 对象，不要多余文字：
{
  "type": "上面五个类型ID之一",
  "event": "符合该类型的诡异描述，1~2句，留白、令人不安"
}
请根据当前异常度选择合适的事件（异常度越高，越倾向更危险/更超现实的类型）。
```

## 四、代码侧改造（AIDirector.cs）

### 解析改造
- 现在 `OnEventGenerated` 只取 `event` 字段显示。
- 改为：解析出 `type` 和 `event` 两个字段。
  - `event` → 照常显示在事件日志（带氛围）。
  - `type` → 交给一个新的「事件执行器」去触发对应后果。

### 新增：事件执行器（EventExecutor，建议）
一个集中处理「事件类型 → 后果」的地方：
```
ExecuteEvent(string type):
  switch type:
    case "storm":          → 风暴后果（MVP 可先只做告警/表现）
    case "space_warp":     → 挑1个NPC瞬移 + 困惑 + 终止任务
    case "time_disorder":  → 时钟动画 + 时间快进 + 结算消耗
    case "causal_reversal":→ 进入延时状态（篡改材料 + 滤镜），计时结束后结算
    case "whisper_vision": → 低语音效 + 生成可对话幻象
```
- 每个 case 调用对应系统（瞬移调位置、快进调时间管理…）。
- 这样「导演选type」和「代码执行后果」彻底分离，符合架构铁律。

### MVP 落地建议（先做能闭环的）
- **最容易、最有"后果感"的先做**：`space_warp`（瞬移）、`time_disorder`（快进）。
  这两个后果明确、复用现有系统、玩家一眼能看到「事件真的影响了世界」。
- `whisper_vision`（可对话幻象）叙事价值最高，但涉及生成幻象NPC+对话，稍复杂，可第二批。
- `storm`、`causal_reversal` 依赖电力/建造系统，可在那些系统完善后再接。

---

## 五、这样升级后达成了什么

1. **事件有后果**：导演事件不再是刷文字，每个都真实改变世界 → 解决最初的痛点。
2. **职责分离**：LLM 只选类型+写描述（创造），代码执行后果（判断）→ 符合架构铁律。
3. **可控可测**：事件类型是有限集合，后果是确定的代码 → 可调试、可做问卷验证。
4. **MVP 可用**：先接 space_warp + time_disorder，就能让玩家感到「导演在真实地影响游戏」。
