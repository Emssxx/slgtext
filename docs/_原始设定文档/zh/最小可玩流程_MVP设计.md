# 亚空间生存SLG — 最小可玩流程（MVP）设计文档

> 本文档定义本作的**第一个能从头玩到尾的最小版本**。
> 目标：用**已有的系统**，串成一个完整的游戏循环，让玩家体验到核心乐趣。
> 这份文档是接下来开发的**主线索引**——不再「想到哪做哪」，而是「为了让这个最小流程跑通，依次做这几件事」。

---

## 一、核心体验（北极星）

> **在亚空间的压迫下，做精神/资源的生存决策。**

所有设计都服务于这一句话。玩家应该时刻感到：
- 压力在累积（NPC会饿、精神会被侵蚀、会出突发状况）；
- 资源/人手不够，必须做取舍；
- 每个决策都有代价，没有完美解。

**MVP 不做：** 污染、电力、终端机、机器人、怪物、防御、怪潮。
这些都已有设计文档存档，是 MVP 验证之后的扩展，现在一概不碰。

---

## 二、最小可玩流程（全部使用现有系统）

```
【开局】
  3 个随机生成的 NPC 在营地。仓库资源有限（几个罐头/水）。异常度低。
  玩家（AI）通过简短开场白知道：你要帮他们在亚空间活下去。
        ↓
【压迫累积】（时间推进，由 AIDirector 的回合驱动）
  · 资源压力：NPC 会饿、会累，仓库在消耗。
  · 精神压力：异常度缓慢上升，NPC 的 SAN 慢慢下降。
  · 突发压力：导演偶尔丢一个亚空间事件，制造麻烦。
        ↓
【玩家决策】（通过对话 + 指挥做取舍）
  · 资源不够 → 派谁去搜寻？（搜寻费体力、离开营地）
  · 某 NPC 的 SAN 低 → 让他休息/远离危险？但人手就少了。
  · 信任不够 → 他不一定听你的，要先经营关系。
  · 出了事件 → 怎么应对（安抚、指挥、调整安排）。
        ↓
【后果】
  · 决策得当 → 大家撑下去，SAN/资源维持住。
  · 决策失当 → NPC 精神崩溃、甚至死亡，局势恶化。
        ↓
【结束条件】
  · 胜：撑过 N 天（如 5 天），且还有 NPC 存活。
  · 负：全员崩溃/死亡。
```

**这就是一个能从头玩到尾的最小游戏。** 每个环节都是已有系统，第一次有了「互相的因果」。

## 三、现有零件核对（好消息：零件基本都有）

| 流程环节 | 用到的系统 | 状态 |
|---|---|---|
| 开局生成 NPC | WorldManager + 词条池 | ✅ 现成 |
| 资源压力（饿/累/搜寻） | NpcDecisionRules + 仓库 | ✅ 现成 |
| 精神压力（SAN衰减） | WorldRules.ApplyTurnEffects | ✅ 现成 |
| 突发压力（事件） | AIDirector | ✅ 现成 |
| 玩家对话了解情况 | ChatManager + NpcAgent | ✅ 现成 |
| 玩家指挥 NPC | TaskPlanner + NpcTaskRunner | ✅ 现成 |
| 信任影响听从 | TrustRules | ✅ 现成 |
| 决策反馈可见 | 日志栏/事件栏/NPC卡 | ✅ 现成 |
| 时间推进（回合） | AIDirector | ✅ 现成 |
| **胜负条件** | —— | ❌ **要补** |
| **开局引导/开场** | —— | ❌ **要补** |
| **整体节奏/手感调校** | （调参数） | ⚠️ **要调** |

**结论：你不缺系统，缺的是 ①胜负条件 ②开局引导 ③把压力的节奏调到「有压迫但不绝望」。**

## 四、要补的连接（这是 MVP 的真正工作量）

### 补丁1：胜负条件（GameManager）★最关键
- 新建一个 GameManager（或在 WorldManager 加逻辑），每回合检查：
  - **胜利**：world.day >= 目标天数（如 5），且至少 1 个 NPC 存活（health>0 且未崩解）。
  - **失败**：所有 NPC 都死亡或崩解。
- 触发胜/负后，显示一个结算画面（简单文字即可：「你们撑过了 X 天」/「全员失守」）。
- 这是 MVP 从「一直跑」变成「一局游戏」的关键。

### 补丁2：开局引导（开场提示）
- 游戏开始时，用聊天框/一个面板给玩家一句开场：
  「你是 ABA 的生存支援 AI。这 3 个人被困在亚空间，你要帮他们活下去。
   亚空间会侵蚀他们的精神，资源也有限。和他们对话，指挥他们行动。」
- 不用做完整教程，就一段话让玩家知道「我是谁、要干嘛、面临什么」。

### 补丁3：节奏/手感调校（调参数，反复试）
- 调 SAN 衰减速度、饥饿速度、异常度上升速度、导演事件频率。
- 目标手感：**有压迫感，但玩家通过合理决策能应对**（不能太快全崩，也不能太闲）。
- 这一步靠「玩 → 调 → 再玩」反复迭代，是 MVP 最花时间但最重要的部分。

### 补丁4（可选）：一个清晰的「当前威胁」提示
- 让玩家一眼看到当前最紧迫的问题（谁快崩了、资源还剩多少、第几天）。
- 可以用现有 UI（状态卡/顶部一个小信息条）。

## 五、实现清单（按优先级，逐个做、做完即测）

> 原则：每做一项就测一次，确认这一环成立，再做下一项。

**第 1 步：胜负条件（GameManager）**
- 做 GameManager，每回合判定胜/负，触发结算画面。
- 测：玩到第 5 天会不会赢？全员崩溃会不会输？

**第 2 步：开局引导**
- 游戏开始给一段开场提示。
- 测：新玩家一上来知不知道自己要干嘛？

**第 3 步：完整跑一遍 + 手感调校**
- 从开局玩到结束（赢或输），看整个循环顺不顺。
- 反复调 SAN/饥饿/异常度/事件频率，调到「有压迫但能应对」。
- 测：玩起来有没有「在压迫下做决策」的感觉？哪里无聊？哪里太难？

**第 4 步：威胁提示（可选）**
- 加当前威胁的清晰提示。

**第 5 步：自己完整玩 N 局 + 给别人玩**
- 自己玩几局，记录：哪里有意思、哪里无聊、哪里困惑。
- 给同学/森田老师玩，收集真实反馈。
- **这一步是 MVP 的终点，也是后续一切的依据。**

## 六、MVP 完成后的判断（重要）

玩过 MVP、收集反馈后，会得到三种可能的结论，每种对应不同的下一步：

1. **核心循环已经有意思** → 太好了。从扩展设计（污染/电力/转化…）里选「最能放大乐趣」的一个，做深。
2. **有潜力但某处无聊/困惑** → 针对那个具体问题改进（可能是手感、可能是反馈不清、可能是决策不够有分量）。
3. **核心循环本身不够吸引人** → 这是最宝贵的发现。**在投入几个月做污染/电力之前发现它，是巨大的幸运。** 据此重新思考核心。

**无论哪种，你都第一次有了「依据」来决策，而不是凭灵感堆机制。**

---

## 七、对毕业设计的意义

- MVP 是你**能拿给森田老师看、能在独立游戏展演示**的第一个「真东西」。
- 它正面回答老师反复问的「玩家在做什么」——玩家在压迫下做生存决策。
- 它把你已有的所有努力（对话/信任/精神/导演/建造）**第一次整合成一个整体**，而不是散落的演示。
- 之后所有的扩展（污染/电力/机器人…），都建立在「已验证好玩的核心」之上，每一分投入都更有把握。

---

## 八、一句话总结

**别再加新系统了。用你已有的零件，补上「胜负条件」和「开局引导」，
把压力节奏调到位，串成一个能从开局玩到结束的最小循环，然后自己玩、给人玩。**

这是你从「一堆能跑的系统」到「第一个真正的游戏」的关键一步。
