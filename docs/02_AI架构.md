# 02 AI 架构

## 最高原则：「LLM 负责表达，代码负责判断」
- 稳定优先，能用规则做的就不用 AI。AI 只出现在规则做不到的地方（无限的对话、涌现的事件、领导者的思考）。
- LLM 调用必须是低频、异步的，不能阻塞游戏主循环。
- 三关判断：需要「创造」还是「判断」？能不能让玩家等？出错时是「表现差」还是「逻辑崩」？

## 硬件与模型
- 开发机：Core Ultra 7 270K Plus、RTX 5080 16GB、32GB 内存。游戏渲染和 LLM 共用显卡。
- 本地：Ollama 14B，不开 reasoning。简单对话约 1〜2 秒，复杂任务约 5 秒。演变过程：qwen2.5 3B → 7B → 14B。
- 云端：用 `IAIClient` 统一接口，`AIClientHub` 负责切换。支持 Claude、OpenAI、Gemini；可以在主菜单里选本地还是云端。API key 放在配置文件里（`apikey.txt`），游戏内有 key 状态提示。没有 key 的人暂时不作为试玩对象。

## 多模型分工（2026-11-05〜07 确定）
- 最初的设想：14B 的算力按 NPC 行为 0.7、AI 导演 0.2、敌人 0.1 分配，再加一个 4B 处理玩家输入。随后改为「NPC 思考优先级最高」。
- **最终方案**：
  - **14B** 主要扮演**领导者**，给其他 NPC 下指令。领导者「发呆」时显示为「思考中」（会加动画）。
  - **4B = 隐形参谋**，只服务领导者。它拿到游戏规则（建筑篇、资源篇、生存篇），分析营地情况后把建议直接交给 14B（不经过玩家），比如短期缺水就报缺水，长期缺水就建议造蓄水器。规则写在 `Assets/Resources/AI/advisor_rules.txt`。
  - 其他 NPC 跟普通 SLG 的 NPC 一样，按指令行动（规则代码）。但玩家找任何 NPC 聊天，都还是交给 14B。
  - 去掉 NPC 对事件的反应台词（事件只记进本地记忆）。
  - 原因：4B 太慢，放在行动链的第一位会让 NPC 发呆。
- 领导者：由 4B 作为观察者，从随机生成的 NPC 里挑出数值最合适的人，在开场演出成「投票选举」。之后会加 NPC 成长系统。
- 玩家对领导者的作用：纠正 NPC（指出哪里做得不对），效果跟信任度挂钩。

## 演员提示词（ActorProfile）
生成 NPC 时，用 LLM 生成一份演员提示词，扮演这个 NPC 时最先读取。格式示例（2026-10-26）：
【职业】【家庭背景】【年龄】【性别】【爱好】【性格】【与 AI 的对话方式】【关于亚空间的认知】，事件态度（【神秘的低语】等），面对死亡（【他人死亡】【朋友死亡】【自己死亡】），面对敌人……
- 不同性格的人对 AI（玩家）的初始信任度和反应都不一样。
- 演员要读取当前的状态词条再回答（饿了就说饿，受伤了就说哪里痛）。
- 每个 NPC 有独立的记忆文件，保留最近 200 条对话上下文。
- 游戏词库（`GameLexicon`）：玩家说「去找急救包」时，从词库里提取关键词，转成指令。

## 指令流程
- 玩家用 chat 下指令 → 关键词匹配为主，AI 作为兜底 → 结构化任务 → 规则代码执行（NavMesh 寻路）。
- 多步指令（去 A 拿东西再去 B）交给 AI 解析成有序列表。
- 网格坐标（例如 G7）可以直接写进指令里。
- NPC 不听指令时，代码会强制约束。
- 跑题或不符合世界观的输入 → `LanguageGuard`/AI 铁律 → 本地预设回复。

## AI 导演
- 目标：超越 RimWorld 的 Storyteller，做到针对当前局势、叙事连贯、不重复。
- 低频触发。事件分类型（空间扭曲、时间失序、低语与幻象等），由 `EventExecutor` 执行实际后果。
- 世界观集中在 `WorldLore` / `WorldRules`，同时注入 NPC 提示词和导演提示词。
- 曾经出现过的问题：导演提示词不走翻译表，导致中文和日语混用 → 语言指令一定要放在最后，不要写死语言。

## 下一步方向（用户的目标）
NPC 能自己判断局势并行动（例如「我觉得应该在这里建一面墙」，然后真的去建），在这之上做 NPC 社交系统。详见 `03_NPC系统.md`。
