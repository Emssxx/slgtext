# 数值速查（方案部碰撞时按需翻）

> 项目里已有的数值（SAN 阶段、健康、信任等）以 `docs/03_NPC系统.md` 和 `decisions.md` 为准，这里只放通用方法。

## 1. 先想清楚的设计概念

| 概念 | 一句话 | 用来检查什么 |
|---|---|---|
| 核心循环 | 玩家反复做的那件事：观察 → 决定 → 结果 → 新局面 | 新功能有没有接进循环 |
| 源与汇 | 资源从哪产出（源），在哪被消耗（汇） | 只有源 → 通胀、没压力；只有汇 → 必死 |
| 正反馈 | 越强越强（雪球） | 领先方会不会一路碾压、落后方无法翻身 |
| 负反馈 | 越强越受限（橡皮筋） | 会不会让玩家觉得努力没用 |
| 有意义的选择 | 每个选项都有代价，没有永远正确的答案 | 有没有「主导策略」（一种做法永远最好） |
| 信息可见性 | 玩家能不能看到做决定需要的信息 | 失败时玩家知不知道为什么失败 |
| 张弛节奏 | 危机和喘息交替 | 压力是不是一直拉满，或者一直没压力 |
| 涌现叙事 | 简单规则互相碰撞，自然产生故事（RimWorld 的故事讲述者） | 规则之间有没有能「碰出故事」的交点 |

## 2. 生存 SLG 常用数值框架

### 每日收支
- 一切数值先折算成**「每天」**：人均每日消耗 × 人数 vs 每日产出。
- **储备天数** = 库存 ÷ 每日净消耗。把它显示给玩家（「食物还能撑 3 天」），比显示库存数字更有压力感。

### 阈值 + 滞后（防抖动）
- 例：SAN 低于 30 进入恐慌，**回到 40 以上**才解除。
- 进入和解除用同一个数字，状态会在边界上来回跳。

### 软上限（收益递减）
- `效果 = 最大值 × x ÷ (x + k)`：x 越大涨得越慢，k 是「涨到一半」需要的量。
- 用在：多人一起干活的效率、堆同一种建筑的收益。

### 曲线怎么选
| 曲线 | 特点 | 适合 |
|---|---|---|
| 线性 | 稳定、好预测 | 基础消耗、简单产出 |
| 指数 | 后期爆炸 | 威胁升级、灾难扩散（要配上限） |
| 对数 | 前期涨得快，后期很平 | 技能熟练度、升级收益 |
| S 曲线 | 慢 → 快 → 慢 | 感染、谣言、情绪在人群中传播 |

### 概率
- 期望值 = 概率 × 结果。先算期望，再决定要不要随机。
- 多次小概率叠加：n 次里至少发生一次 = `1 − (1 − p)^n`。例：每天 5%，10 天里至少一次 ≈ 40%。
- **保底 / 伪随机**：连续失败就提高概率，避免玩家觉得「被骰子针对」。

### 四个常见病
1. **死亡螺旋**：一个坏事引发更多坏事，玩家无法挽回 → 加一个保底或缓冲。
2. **滚雪球**：优势越滚越大，后期没压力 → 加消耗或事件压力。
3. **主导策略**：有一种做法永远最好 → 给它加代价，或者给其他选项加独特收益。
4. **理解成本**：玩家要算很久才知道该怎么做 → 简化，或者把关键数字直接显示出来。

## 5. 参考作品可以借什么

| 作品 | 可以借鉴 |
|---|---|
| RimWorld | 故事讲述者控制事件节奏；心情阈值导致崩溃；角色特性制造冲突 |
| Frostpunk | 希望 / 不满两条条；法典让玩家做道德取舍；寒潮倒计时 |

| 潜渊症 | 多系统同时故障；船员各有职责；外部威胁加内部混乱 |
| This War of Mine | 白天躲、晚上搜的节奏；道德负担影响角色状态 |
