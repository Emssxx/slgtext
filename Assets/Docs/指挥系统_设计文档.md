# 网格坐标 + Chat/点击 指挥系统 — 设计文档

> 项目：亚空间生存 SLG
> 本文档定义"玩家如何指挥 NPC 在地图上行动与建造"的完整系统。
> 状态：设计阶段（暂未实现代码）

---

## 0. 这个系统在整个游戏里的定位

游戏的核心定位：**一个由 AI 驱动的"活体世界"沙盒**。玩家扮演一个只能用语言交流的 AI，
在一个有真实生存约束的传统 SLG 世界里，引导一群有真实人格的幸存者。

AI（LLM）的职责边界（已明确）：
- LLM 负责：NPC 对话、AI 导演事件、理解玩家自然语言指令。（低频、可等待，适合 LLM）
- LLM 不负责：NPC 行为决策、移动逻辑。（高频、要流畅，走规则，像 RimWorld）

本指挥系统服务于"玩家如何与世界交互"，其中：
- **普通模式**：玩家与 NPC 普通对话（沉浸），不能直接控制 NPC 移动，NPC 自主行动（规则驱动）。
- **建造模式**：地图显示网格，玩家可通过点击或 chat 指定位置，指挥 NPC 建造。

---

## 1. 核心设计决策（已拍板）

### 1.1 坐标形式：方案3 —— 底层网格 + 语义叠加
- **底层**：地图划分为网格，每格有精确坐标 (x, y) 和编号（如 G7）。代码层一律用网格坐标。
- **展示层**：给玩家看时，叠加语义位置（如"仓库东侧 (G7)"），既精确又沉浸。
- **输入层**：玩家既能说精确编号（"G7"），也能说语义（"仓库旁"），系统都能映射到具体格子。
- 实现策略：先做底层网格内核，语义层后续叠加（见分阶段计划）。

### 1.2 交互分两种模式
| | 普通模式 | 建造模式 |
|---|---|---|
| 玩家能做什么 | 和 NPC 对话（沉浸） | 指挥 NPC 建造（操作） |
| NPC 移动 | 自主（规则 / RimWorld 式） | 听指挥去指定格子 |
| LLM 角色 | 对话（可等待几秒） | 几乎不参与（或仅解析自然语言指令） |
| 延迟敏感度 | 低（玩家预期它在"想"） | 高（用代码，零延迟） |

> 关键洞察：这种分离**天然解决了 LLM 延迟问题**——需要快的（操作）走代码，能等的（对话）走 LLM。

### 1.3 三种输入方式都支持（建造模式下）
- **纯点击流**：选建造物 → 点格子 → 直接下令（最快，传统 SLG 玩家用）。
- **Chat 流**：打字"在 G7 盖墙"（自然语言，体现 AI 卖点，较慢）。
- **混合流**：点格子自动把坐标填进 chat，玩家只需补"盖墙"（省去打坐标，平衡）。

> 三者并存：保住 AI 卖点（chat），又保证可用性（点击）。

### 1.4 NPC 是"麻烦"的来源之一（重要玩法支柱）
- 玩家**不能像 RTS 那样直接操控** NPC，只能通过对话/指令影响。
- NPC 听不听、做不做得到，**有不确定性**（受精神状态、性格影响）。
- 于是 NPC 本身成为一种需要"管理"的麻烦——SLG 张力与人性在此融合，不缝合。
- **平衡待定**（见第 4 节待解决问题）：危急时必须自保，不能蠢到自杀，否则玩家抓狂。

## 2. 模块拆解（从底层到上层）

```
1. 网格系统 GridManager        —— 地基，最先做
2. 坐标解析 GridCoordParser     —— 从文字认出坐标
3. 点击输入 GridClickInput      —— 鼠标点格子
4. 建造指令 BuildCommand        —— 把"在G7盖墙"变成可执行任务
5. NPC 执行（复用现有）          —— NpcTaskRunner 走到格子+建造
```

### 2.1 GridManager（网格系统 — 地基）
职责：把地图划分成网格，提供坐标互转和格子状态。

```
字段：
  gridWidth, gridHeight   // 地图多少格（如 30×20）
  cellSize = 1            // 每格世界尺寸（配合 Tilemap：1格=1单位，PPU=32）
  origin                  // 网格左下角的世界坐标
  occupied[x, y]          // 记录每格被什么占用（空/建筑/障碍）

方法：
  WorldToCell(世界坐标) → 格子(x,y)      // 鼠标点击用
  CellToWorld(格子x,y) → 世界坐标         // NPC 寻路目标用（给 NavMesh）
  CellToLabel(x,y) → "G7"                // 显示给玩家
  LabelToCell("G7") → 格子(x,y)          // 解析玩家输入
  IsBuildable(x,y) → bool                // 这格能不能建（边界/占用/地形）
```

与现有系统对接：
- 格子坐标 → CellToWorld → 世界坐标 → 作为 NavMesh 寻路目标（接 NpcMover）。
- 配合现有 Tilemap（1 格 = 1 单位），网格尺寸与瓦片对齐。

### 2.2 GridCoordParser（坐标解析）
职责：从玩家文字里认出位置，返回具体格子。
- 识别格式：编号"G7"、数对"(7,3)"、（阶段3）语义"仓库旁"。
- 阶段1 只做编号/数对（纯代码，零延迟）；语义解析阶段3 再加（可能借 LLM）。

### 2.3 GridClickInput（点击输入）
职责：建造模式下，处理鼠标点击。
- 点击 → WorldToCell 得到格子 → 高亮该格 → 把坐标填进 chat 输入框（或直接选中待建造）。
- 需要建造模式的开关（进入/退出建造模式时启用/禁用）。

### 2.4 BuildCommand（建造指令）
职责：把一条指令解析成可执行的建造任务。
- 输入："在 G7 盖墙" 或 点击流的 {物体:墙, 位置:G7}
- 解析出：{ 动作: 建造, 物体类型: 墙, 目标格子: G7 }
- 校验：该格 IsBuildable？资源够不够？
- 派发：交给某个 NPC 的 NpcTaskRunner 去执行。

### 2.5 NPC 执行（复用现有 NpcTaskRunner）
- 复用已实现的任务队列：走到目标格子（CellToWorld → NavMesh 寻路）。
- 到达后播建造动画（新增 build 动作，类似已有的 act/idle2 占位）。
- 建造完成：在该格生成建筑物，更新 occupied[x,y]，扣除资源。

## 3. 分阶段实现计划

### 阶段1（先做）：纯网格 + 点击 + 简单建造
目标：跑通"点格子让 NPC 去那盖个东西"的最小闭环。
- GridManager 核心（坐标互转、IsBuildable、occupied）。
- GridClickInput（点击选格、高亮）。
- BuildCommand（点击流：选物体→点格→下令，纯代码不走 AI）。
- NPC 走到格子 + 建造动画 + 生成建筑。
- **验证**：建造模式下点一个格子，NPC 走过去盖一堵墙，墙出现在格子上，资源扣除。

### 阶段2（再加）：Chat 自然语言指挥
目标：打字也能指挥建造。
- GridCoordParser 接入文字解析（"在 G7 盖墙"）。
- 自然语言指令部分走 AI（理解意图），坐标部分走代码（精确）。
- **验证**：在 chat 输入"在 G7 盖墙"，NPC 执行。

### 阶段3（打磨）：语义坐标 + 混合输入
目标：沉浸 + 顺手。
- 语义层：CellToLabel 叠加语义（"仓库东侧 (G7)"）；支持"仓库旁"映射到格子。
- 混合输入：点格子自动填 chat（点了 G7，输入框出现"在 G7 "，玩家补"盖墙"）。
- **验证**：点击和语义都顺畅，体验既沉浸又高效。

## 4. 待解决的问题（设计未定，需后续讨论）

### 4.1 NPC 不听话的"度"
- 哪些指令 NPC **一定**执行（保证玩家不失控）？
- 哪些情况 NPC **可能**抗命（精神崩溃、性格抵触）？
- 危急自保底线（快死了会自救，不蠢死）怎么设计？
- 目标：制造"管理不完全听话的人"的张力，但不让玩家抓狂。

### 4.2 语义坐标的具体映射
- 语义区域（"仓库旁"）覆盖哪些格子？范围怎么定义？
- 多个 NPC/建筑同名区域如何消歧？
- 棋盘编号（A1-Z99）对玩家是否够直观，还是主要靠语义？

### 4.3 建造系统本身的深度（属于"传统 SLG 舞台"，另行设计）
- 有哪些可建造物（墙/床/工作台/储物…）？
- 建造消耗什么资源？建造耗时？
- 科技树如何与建造解锁挂钩？
- 注：建造深度做"够用"即可，核心精力留给 AI 导演与对话。

## 5. 硬件约束备忘（影响所有 LLM 相关设计）
- 机器：3080 laptop，8G 显存，跑 qwen2.5:7b（本地 Ollama）。
- 游戏渲染与 LLM 抢同一块显存；LLM 生成有几秒延迟。
- 设计铁律：**LLM 只出现在低频、可等待的环节**（对话、导演事件、自然语言指令解析）。
  实时高频环节（移动、建造执行）一律走代码。
- 模型层建议做成可切换（本地 Ollama / 云端 API），开发用本地，参展可选云端。
- 本指挥系统的"点击流/混合流"正是为绕开 LLM 延迟而设计——建造操作不依赖 LLM。
