# 亚空间生存 SLG — 游戏架构总纲

> 本文档是整个项目的架构基准。任何新功能、任何重构，都以本文档为准。
> 核心定位：**一个由 AI 驱动的"活体世界"沙盒**——玩家作为只能用语言交流的 AI，
> 在一个有真实生存约束的传统 SLG 世界里，引导一群有真实人格的幸存者。
> 项目本质：**探究 AI（LLM）在游戏中的可能性**。

---

## 第一部分：最高原则

### 原则 1：代码算数 → 4B 判断 → 14B 决策与演绎 → 代码执行

> 2026-11-06 修订：原来的"LLM 只做三件事、绝不碰行为决策"已经退役。
> 现在 AI 可以参与决策，但只能在代码划好的边界里做，执行和数值永远归代码。

**四步流程：**
1. **代码算数**：把世界整理成数字和事实（净化水还够几秒、围墙还差几段、谁受伤了……）。小模型算数不可靠，数字一律由代码先算好。
2. **4B 判断**（小模型，隐形的营地参谋 CampAdvisor 等）：读规则手册 + 局势表，推出营地眼下最要紧的事；也负责选领导的观察、闲聊语气判断、短台词。
3. **14B 决策与演绎**（主模型）：参考 4B 的判断，做领导分工、NPC 自主意图；以及 NPC 对话、AI 导演事件、玩家自然语言指令解析。
4. **代码执行**：审核 AI 的选择，拆成任务链（寻路、取材料、施工），并结算所有数值。

**AI 可以做（白名单）：**
1. NPC 对话生成（玩家对话 / 危急自语 / 对事件的反应）
2. AI 导演事件生成（亚空间异常事件）
3. 自然语言指令解析（把玩家的话变成结构化任务）
4. 低频的高层决策：NPC 自主意图、领导分工、建造项目——**只能从代码给的选项清单里选**
5. 小模型的辅助判断：营地局势、谁适合当领导、闲聊语气（结论交给代码或 14B 参考）

**AI 绝对不碰（黑名单）：**
- 移动、寻路、具体执行步骤
- 直接改数值：信任 / 好感 / 尊重、听不听指令、生命、理智、世界规则结算（AI 只读不写，代码按发生的事结算）
- 任何每帧 / 高频 / 玩家等着看结果的逻辑（需求、遇险逃跑等）

**加 AI 功能前的判断口诀（三关全过才用 AI）：**
1. 它是低频、玩家可等待的吗？（否→规则）
2. 出错时是"表现差"还是"逻辑崩"？（逻辑崩→规则，或代码审核 + 兜底）
3. AI 的输出能被代码检查吗？（只能从清单里选、代码能验证的，才交给 AI 决策）

**每个 AI 功能都必须有：** 走 AiScheduler 排队（优先级、过期作废、限额）+ 代码兜底（没开模型 / 出错 / 超时也能继续玩）。

### 原则 2：硬件约束是铁律
- 机器：GPU 显存 8GB，游戏渲染与 LLM 共享。LLM 应答有数秒延迟。
- 因此 LLM 调用必须低频、异步、不阻塞游戏主循环。
- 模型来源做成可切换（本地 Ollama / 云端 API），开发用本地，发表可选云端。

### 原则 3：先规则后 AI，能用规则就不用 AI
- 稳定性优先。规则透明、可调、零延迟、可预测。
- AI 只在规则做不到的地方（无限对话、涌现事件、需要"看懂局势"的高层决策）登场，而且必须有规则兜底。

## 第二部分：分层架构

```
┌─────────────────────────────────────────────────────┐
│ A. 玩家交互层                                           │
│    普通模式（对话）/ 建造模式（网格指挥）                  │
├─────────────────────────────────────────────────────┤
│ B. AI 层（低频可等待 · 经 AiScheduler 排队 · 有代码兜底）  │
│    14B：对话 / 导演事件 / 指令解析 / 自主意图 / 领导分工   │
│    4B ：营地参谋 / 领导观察 / 语气判断 / 短台词            │
├─────────────────────────────────────────────────────┤
│ C. 执行层（规则代码 · 高频实时 · 不走LLM）                 │
│    需求状态机 / 任务链执行 / 移动寻路 / 听从判定 / 关系结算 │
├─────────────────────────────────────────────────────┤
│ D. 系统服务层（规则代码）                                │
│    精神状态系统 / 世界规则 / 关系系统 / 本地化 / AI客户端   │
├─────────────────────────────────────────────────────┤
│ E. 数据层                                              │
│    NPC数据(属性+信任+关系) / 世界状态 / 世界观文本         │
└─────────────────────────────────────────────────────┘
```

数据流向：E（数据）→ C/D（规则处理、算好局势）→ B（4B 判断 → 14B 决策 / 表达）→ C（代码审核并执行）→ A（呈现给玩家）。
玩家输入：A → （建造指令走 C 纯代码 / 对话走 B 的 LLM）→ 反馈。

## 第四部分：NPC 完整设计（重构核心）

### 4.1 NPC = 数据（词条池随机生成）+ 规则行为 + LLM对话

NPC 的三层对应总架构：
- **数据层**：属性 + 信任 + 关系（见下）
- **需求层**：行为决策状态机（纯规则：饿、累、逃命等生理需求，优先级最高）
- **意图层**：安全感不足 / 紧急情况 / 领导分工时，由 AI 在代码给的清单里选目标，代码拆成任务链执行（见 NpcIntents、NpcSociety）
- **表达层**：LLM 把行为 / 状态 / 想法用人格化语言说出来

### 4.2 NPC 生成：全部词条池随机（手捏人物卡退役）

旧的手捏 NpcProfile（老五/李四）**退役**。改为多维词条池随机组合：
- 维度1：性别 + 主性格（开朗/阴沉/暴躁/冷静/怯懦/勇敢…）
- 维度2：社交性（话痨/寡言/毒舌/温和…）
- 维度3：职业（教师/医生/军人/消防员/学生…）
- 维度4（可选）：癖好/创伤（念旧/洁癖/怕黑/失去家人…）

每个词条自带：① 给 LLM 的描述文字 ② （可选）影响规则的数值倾向（如"勇敢"降低逃跑阈值）。
生成时各维度抽一个，组合出独一无二的 NPC。

### 4.3 行为决策状态机（NpcDecisionRules 升级，纯规则）

无玩家指令时，NPC 按优先级规则自主行动（不走 LLM）：
```
优先级从上到下，命中即执行：
  1. 理智≤1        → 崩解（不决策，走 BrokenSpeech）
  2. 生命危急       → 求救/逃跑
  3. 饥饿>阈值      → 吃东西
  4. 体力<阈值      → 休息
  5. 物资不足       → 搜寻
  6. （安全时）默认  → 待命/闲逛
阈值受性格词条影响（如勇敢者逃跑阈值更低）。
```
> 2026-11-06 补充：第 5、6 条之间现在多了"意图层"——有分工的人按分工由代码干活；
> 没分工的人在安全感不足或营地参谋发现紧急情况时，由 AI 决定做什么。1～4 条的生理需求永远优先。

### 4.4 信任度（对玩家）→ 听不听指令

- playerTrust (0~100)，决定听从概率（曲线见 TrustRules）。
- 完全按信任度，不做保命例外（信任高则听，哪怕送死）。
- 只管听/不听 + 简单拒绝台词，不做过多反应。

### 4.5 关系系统（NPC↔NPC，重点打磨，单向）

- 每条关系：trust（信任0~100）+ affinity（友善-100~100）。
- 单向：A→B 和 B→A 独立，可不对称。
- 影响（分阶段实现）：对话语气、合作意愿、关系者崩溃/死亡冲击SAN、涌现冲突、动态变化。

## 第五部分：玩家交互（两种模式）

### 普通模式
- 玩家与 NPC 普通对话（走 LLM，沉浸）。
- 不能直接操控 NPC 移动（NPC 自主行动）。
- NPC 因人格/精神状态不完全听话 → 本身成为"要管理的麻烦"。

### 建造模式
- 地图显示网格，每格有坐标（底层网格 + 语义叠加，见指挥系统设计文档）。
- 三种输入：纯点击 / chat自然语言 / 混合（点击填坐标+补指令）。
- 建造操作走纯代码（零延迟），不依赖 LLM。

> 指挥系统详见单独文档《指挥系统_设计文档》。

## 第六部分：世界观注入（WorldLore）

- 世界观文本集中在 WorldLore，从两个出口注入：
  - NPC 提示词（对话氛围）
  - AI导演提示词（事件素材）
- 语言指令必须放在提示词**最末尾**（近因效应，否则被长文淹没）。
- 提示词里禁止写死语言（如"（中文）"），语言统一由本地化的语言指令控制。

## 第七部分：AI导演（最大特色，重点投入）

目标：超越 RimWorld 的 Storyteller（从固定事件库抽取）——
做到**情境化（针对玩家当前痛点）、叙事连贯、无限不重复**的即兴事件生成。
- 低频触发（每隔数分钟一回合），适合 LLM。
- 事件生成后写入世界记录，NPC 后续"知道"发生过。
- 可点名 NPC 对事件做出反应。
```
